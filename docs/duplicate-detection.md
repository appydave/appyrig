# Duplicate detection

`npm run lint:duplicates` runs five jscpd 5.4.1 profiles: exact (Type 1), renamed identifiers,
fully renamed (identifiers, literals, annotations), near-miss (syntax-tree similarity plus gap
merging) and semantic (embeddings). Every profile fails the build on a clone that is not in its
baseline (`.jscpd/<profile>.json`). The settings live in `package.json` (`lint:duplicates:*`) and
the shared scope in `.jscpd.json`; this page records why they are what they are.

## Baseline, then ratchet

The code already holds clones, so each profile records today's clones in `.jscpd/<profile>.json`
and fails only a **new** one (`--fail-on-new-clones 0`). The baselines may shrink as clones are
removed (`npm run lint:duplicates:<profile> -- --update-baseline` after a fix); they never grow.

## Scope

All tracked code, tests, e2e, scripts, YAML, JSON and Markdown. Left out, because they are generated,
captured or vendored data rather than an implementation to share:

- `api/**` (generated by `api:gen`), the two generated `client/src/domain/learn/*.json` files,
- `test/fixtures/**` and `test/root/fixtures/**` (captured OpenRig output and vendored spec files),
- content tables with no logic: `client/src/domain/learn/{commands,glossary,lessons}.ts` and
  `client/src/kit/v1ArchiveManifest.ts` (literal normalization flags every table as a clone),
- `**/*.css` (the Stylelint ratchet owns styles; repeated declaration lists are not shareable code),
- `.mochaccino/**` (design mockups), `.claude/**` (agent skills).

No application source or test directory is excluded for producing inconvenient matches.

## Calibration (read on 2026-10-22, tree `be3c610`)

A reported pair counts as a false alarm when the two spans share no implementation that could sensibly
live in one place (similar-looking independent assertions, fixture data, configuration values).
Ambiguous pairs count against a setting. Under 3% is the target; this is a manual reading, not a
computed rate.

| Profile       | Selected                                          | Pairs reported | False alarms | Next-more-sensitive setting tried                            |
| ------------- | ------------------------------------------------- | -------------: | -----------: | ------------------------------------------------------------ |
| `exact`       | 90 tokens / 9 lines                               |             36 |            0 | 85: 2 of 47 false (fixture data, inline YAML strings)        |
| `identifiers` | 130 tokens / 16 lines                             |              7 |            0 | 120: 1 of 8 false (optional-field pairs in an options type)  |
| `renamed`     | 240 tokens / 1 line                               |              5 |            0 | 204: 4 of 10 false (data tables, a markdown table)           |
| `similar`     | AST 0.85, min-nodes 40, gap 12, 60 tokens / 5 ln. |             14 |            0 | AST 0.75: `apiSuccess`/`apiError` false; tokens 40: 3 of 23  |
| `semantic`    | CodeRankEmbed, 0.90, 36 tokens / 1 line           |            144 |            3 | 0.84: 12 of 203 false (2-line `flatMap` calls, `it()` pairs) |

Notes that decided settings:

- `exact` 60 and 70 tokens also report CSS declaration lists, Playwright step runs and per-case test
  bodies; 80 admits two fixture pairs.
- `--ignore-literals` on its own was not used: on the content tables every hit was a false alarm.
- `similar`: AST similarity only matters for 3 pairs here (test files are skipped by the AST pass); the
  rest are gap-merged near-copies. Gap 12 and 6 report the same pairs; tokens decide the false rate.
- `semantic` reports every pair in a clique (the xterm mock repeats in 13 test files and is reported as 40
  pairs), which is why the count is large. Three pairs at or above 0.90 are false alarms (two
  `it.each` lines, a 5-line `toasts.map`, a `cov` fixture helper). Four reported pairs sit within 0.005
  of the cutoff.

## Semantic model and CI

The semantic profile downloads a checksum-verified CodeRankEmbed model on first use (about 548 MB,
CPU only, no hosted API; jscpd 5.4.1 pins the revision). First run on an M4 Mini took about 4.5 minutes
(3,759 functions embedded); a rerun against the cache takes about a second. The `duplicates` CI job
caches `.quality-results/jscpd-cache` per engine, model, runner and a hash of the TypeScript files, and
uploads the JSON reports. Embedding scores can differ slightly between macOS and Linux; review borderline
pairs when upgrading tools or if the CI job disagrees with the local baseline.

Blind spots: AST similarity skips test files; semantic compares across files, not within one; unsupported
languages and very short snippets are not covered.
